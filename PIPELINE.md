# Automated Papercraft Pipeline (`papikapi-studio`)

Deterministic generative pipeline that turns a text prompt and optional reference photos into an axonometric papercraft design (Stage 1), cuts it out and synthesizes a production-ready 3D model (Stage 2). Stage 3 unfolds the result into printable, coloured A4 sheets.

---

## 🏛️ Architecture Overview

The pipeline is implemented entirely in strict **TypeScript (`.ts`)** under Node 24 with `tsx`, abandoning all legacy Python scripts and ad-hoc `.mjs` utilities. Every module follows the **Single Responsibility Principle (SRP)** and object-oriented design:

```text
apps/papikapi-studio/

├── resources/                    # Development working area (per model)
│   └── [model]/
```

## ⚙️ Configuration: `pipeline.json`

Every prompt, system instruction, maturity progression, aspect ratio, image dimension, and GPU endpoint is declared in [`pipeline.json`](./pipeline.json). No hardcoded prompts exist in TypeScript code.

### Pipeline Stages Definition

1. **Stage 1: Art Alternatives & Selection**
   * **Step 1 (`s1-step-1`)**: `scripts/stage-1/step-1-alternatives.ts`
     * Input: Prompt description + up to 3 optional photo references.
     * Model: `black-forest-labs/FLUX.2-klein-4B` on RunPod Serverless (aspect ratio 3:2), see `pipeline.json`.
     * Output: `step-1-alternatives.jpeg` (3 columns x 2 rows grid).
     * Style Progression: 6 cells arranged from childlike/chibi (cell 1) to mature/realistic papercraft (cell 6), all sharing a clean 3/4 axonometric perspective on a neutral `#E5E5E5` backdrop.
   * **Step 2 (`s1-step-2`)**: `scripts/stage-1/step-2-pick.ts`
     * Input: `step-1-alternatives.jpeg` + cell number (`1..6`).
     * Output: `resources/<model>/stage-1/step-1-art.jpeg` and `public/models/<model>/art.jpeg`.

2. **Stage 2: Cutout & 3D Model Generation**
   * **Step 1 (`s2-step-1`, CUTOUT)**: `scripts/stage-2/step-1-cutout.ts`
     * Input: `resources/<model>/stage-1/step-1-art.jpeg`.
     * Engine: local `briaai/RMBG-1.4` (`@xenova/transformers`, `canvas`), about 2 seconds, $0.00. Removes the background and floor shadow.
     * Output: `resources/<model>/stage-2/step-1-art-cutout.png` and `public/models/<model>/art-cutout.png`, plus a per-pick copy.
   * **Step 2 (`s2-step-2`, 3D-GLB)**: `scripts/stage-2/step-2-trellis.ts`
     * Input: the transparent cutout from step 1.
     * Service: `microsoft/TRELLIS-image-large` on RunPod Serverless (RTX 4090 worker, scale to zero).
     * Parameters: `simplify: 0.85`, `target_faces: 4000`, `texture_size: 1024`, `seed: 1`.
     * Output: `resources/<model>/stage-2/step-2-3d.glb`, per-pick copies and `step-2-manifest.json`.
   * **Step 3 (`s2-step-3`, BASE)**: `scripts/stage-2/step-3-base.ts` runs `scripts/stage-2/blender/base/cut_base.py` in Blender headless.
     * Input: `resources/<model>/stage-2/step-2-3d.glb`, or `step-2-3d-pick-{pick}.glb` with `--pick`.
     * Removes disconnected islands (when the TRELLIS plinth is a separate island, as in the fire-truck, nothing is cut and the contact band is flattened onto z=0), cuts the TRELLIS plinth away just above its real surface (95th percentile of the height of the plinth top plus a margin of the figure height, starting at 0.3% so the paws keep almost all of their height; `base_cut_margin_ratios` lists progressively larger margins and the first one that gives an airtight mesh is used, `marginRatio` in the manifest says which), caps every foot cross-section flat, and seats the figure on the plane z=0 centred on x=0, y=0.
     * No plinth exists anywhere in the pipeline until step 6, so the texture step never sees one.
     * Output: `step-3-base.glb` and `step-3-manifest.json`.
   * **Step 4 (`s2-step-4`, SIMPLIFY)**: `scripts/stage-2/step-4-simplify.ts` runs `scripts/stage-2/blender/key_points/key_points.py` in Blender headless.
     * Input: `resources/<model>/stage-2/step-3-base.glb`.
     * Output: `step-4-reduce.glb`, `step-4-reduce.json` (vertices and planar face geometry) and `step-4-manifest.json`. No `.blend` files are written anywhere in the pipeline.
     * Simplification: Decimate (collapse, quadric error) reduces to `target_faces` triangles (600), joins planar triangles into quads, and subdivides faces exceeding `face_max_extent_ratio`.
     * Quality: `airtight`, `openEdges`, `nonManifoldEdges`, `maxDeviationMm`.
   * **Step 5 (`s2-step-5`, TEXTURIZE)**: `scripts/stage-2/step-5-texturize.ts` runs `scripts/stage-2/blender/texturize/texturize.py` in Blender headless, with a helper in the system Python (`scripts/stage-2/python/art_flow.py`, OpenCV; executable in `parameters.python_executable`). Generic: nothing is specific to a model.
     * Input: `step-1-art-cutout.png` (the art), `step-2-3d.glb` (TRELLIS: where the elements are) and `step-4-reduce.json` (reduced mesh).
     * **TRELLIS decides where, the art decides how it looks.** The TRELLIS mesh is aligned to the reduced mesh by nearest-point registration; the art camera is recovered by silhouette registration against the cutout (several candidate views, including the opposite one, are ranked by colour agreement with the TRELLIS texture, which settles the front/back ambiguity), refined photometrically (azimuth, elevation, scale, shift, perspective).
     * **Alignment:** the TRELLIS view is rasterised in the art's pixel space and a dense optical flow (DIS) between it and the art is computed and smoothed (`flow_sigma_ratio`, a few percent of the image) so it moves each element to the position TRELLIS gives it without bending the element (the raw flow tears eyes and spots). Each TRELLIS vertex reads the art at its projected position plus that displacement.
     * **Definition:** the art (486 px) is enlarged `art_upscale_factor` times (cubic, edge-preserving filter, sharpening) with its colours spread beyond the cutout so there is no dark halo.
     * **Symmetry for the hidden side:** up to three vertical symmetry planes are searched on the TRELLIS mesh (reflection error below 2% of the length); the one whose mirrored art agrees best with the TRELLIS colours is used, and mirroring is disabled when none agrees (asymmetric figures). Hidden faces whose mirror image is a frontal face (`facing >= 0.68`) take the art of that face; the others keep the TRELLIS colours. Faces facing the camera (`>= 0.5`, not occluded) use the art directly.
     * A Cycles bake with a smooth cage (colours continuous across edges) writes one atlas of per-face islands at about 4.5 texels per mm (`atlas_size_px` 4096, JPEG in the GLB). The geometry is never changed.
     * Output: `step-5-texturize.glb` and `step-5-manifest.json` (`azimuth`, `elevation`, `silhouetteScore`, `colourDisagreement`, `visibleShare`, `symmetryError`, `mirrorColourDisagreement`, `mirroredShare`).
   * **Step 6 (`s2-step-6`, PLINTH)**: `scripts/stage-2/step-6-plinth.ts` runs `scripts/stage-2/blender/plinth/build_plinth.py`.
     * Input: `step-4-reduce.json` and `step-5-texturize.glb`.
     * Deletes the flat foot caps, builds a white trapezoidal plinth with the footprint (length and width, plus `plinth_margin_ratio`) of the figure and fuses it to the feet loops into an airtight mesh, on both the reduced quad mesh and the textured mesh (white material for the new faces).
     * Output: `step-6-plinth.json` (consumed by stage 3), `step-6-plinth.glb` (copied to `public/models/<model>/model.glb`) and `step-6-manifest.json`.

3. **Stage 3: Papercraft Unfolding & Booklet Export** 
   * **Step 1 (`s3-step-1`, UNFOLD)**: `scripts/stage-3/step-1-unfold.ts` runs `scripts/stage-3/blender/unfold_model.py` in Blender headless.
     * Input: `resources/<model>/stage-2/step-6-plinth.json` (the reduced quad mesh with the plinth).
     * Scales longest side to `target_size_mm` (300 mm). Unfolds faces into printable 2D net parts, cuts, fold lines, and tabs.
     * Output: `resources/<model>/stage-3/step-1-net.json` (pieces, plus the repaired mesh and its scale so later steps rebuild it without any `.blend`) and `step-1-manifest.json`.
   * **Step 2 (`s3-step-2`, SHEETS)**: `scripts/stage-3/step-2-sheets.ts` builds the assembly booklet `resources/<model>/stage-3/step-2-sheets.pdf`, copied to `public/models/<model>/sheets.pdf`.
     * Input: `step-1-net.json` + `resources/<model>/stage-2/step-6-plinth.glb`.
     * Colour: the packer places every piece first; the placements become the UV of the mesh (one image per A4 sheet, page millimetres), and a Cycles bake from the textured GLB (smooth cage, `texture_bleed_mm` of colour beyond the cut) writes one JPEG per sheet at `texture_dpi` (200). The PDF draws that image 1:1 under the cut and fold lines, tabs and numbers, so nothing is resampled or rotated afterwards. The white plinth prints white. The sheet images and layout are temporary and removed after the PDF is built.
     * Renders step-by-step assembly diagrams.
     * Compiles complete multi-page PDF assembly guide.
     * Step pages, four per page: the step render with the edges to glue marked by their numbers, a thumbnail of the part, the sheet it is printed on and which edges join which parts.
     * Template sheets: each tab side is chosen so the tab never overlaps its own part (`tab_height_mm`, shrinking when needed); numbers are `edge_number_mm` high, slide along their edge to avoid each other, and appear only on the tab side of a dart. Parts are nested by shape on a `nesting_cell_mm` grid, in any of four quarter turns, `piece_gap_mm` apart, trying several orders and keeping the one with the fewest sheets.
     * `step-2-manifest.json` holds pages, template sheets, parts and `labelCollisions` (overlapping numbers, which must be 0).
     * Language: `workspace.sheet_language` (`pt` or `en`) picks the entry of `scripts/stage-3/sheet-translations.json`, which holds every text of the booklet.
   * The Blender executable, scripts, size, page, margins and every limit above are declared in `pipeline.json`.

## 🚀 Execution Commands

All stages and steps are executed through Nx (`nx run papikapi-studio:...`):

```bash
# Run Stage 1 Step 1 (generate 3x2 alternatives grid for a subject)
nx run papikapi-studio:stage:1:step:1 --model=cheetah --ref=resources/cheetah/stage-1/step-1-art.jpeg --prompt="A cute baby cheetah cub sitting down, identical pose and spots, clean low-poly papercraft facets without black crease lines"

# Run Stage 1 Step 2 (pick cell 4 as final art)
nx run papikapi-studio:stage:1:step:2 --model=cheetah --pick=4

# Run Stage 2 Step 1 (transparent cutout)
nx run papikapi-studio:stage:2:step:1 --model=cheetah

# Run Stage 2 Step 2 (synthesize 3D mesh via RunPod GPU)
nx run papikapi-studio:stage:2:step:2 --model=cheetah

# Run Stage 2 Step 3 (cut the TRELLIS base, feet on z=0, Blender headless)
nx run papikapi-studio:stage:2:step:3 --model=cheetah

# Run Stage 2 Step 4 (key points mesh reduction, Blender headless)
nx run papikapi-studio:stage:2:step:4 --model=cheetah

# Run Stage 2 Step 5 (art PNG projection and bake, Blender headless)
nx run papikapi-studio:stage:2:step:5 --model=cheetah

# Run Stage 2 Step 6 (white plinth fused to the feet, Blender headless)
nx run papikapi-studio:stage:2:step:6 --model=cheetah

# Run Stage 3 (unfold with Blender and export the A4 PDF)
nx run papikapi-studio:stage:3 --model=cheetah

# Run complete Stage 1 or Stage 2 for a model
nx run papikapi-studio:stage:1 --model=cheetah
nx run papikapi-studio:stage:2 --model=cheetah

# Process all discovered models across Stage 2
nx run papikapi-studio:stage:2

# Run every stage for every model
nx run papikapi-studio:stages
```

Before each step the orchestrator checks the files listed in the step's `inputs` (any `*_resource`, its `--pick` variant and the allowed extensions). A step with a missing input is reported as `SKIP`, deletes nothing, and the run carries on with the next step, so a model runs from the first step whose assets exist. Only a step that ran and failed stops that model. When everything is run (`stages`, no `--stage` and no `--step`), a step whose output files already exist is skipped too, so nothing is regenerated or paid for twice. `--stage N` and `--step` regenerate, except a step flagged `skip_if_outputs_exist` (`s1-step-1`, which calls a paid API), which is skipped when its outputs exist unless it is requested by name with `--step`.

### Local API Server for Studio UI

```bash
# Start backend API bridge on port 4502
npx nx run papikapi-studio:server

# In a separate terminal, launch the Angular Studio
npm start -- papikapi-studio
```

The Studio UI proxies `/api` requests to `http://localhost:4502`:
* `POST /api/creator/generate`: Generates the 3x2 alternatives grid.
* `POST /api/creator/pick`: Crops the chosen figure and triggers automatic 3D TRELLIS generation.
* `GET /api/health`: Health status of the local server and remote RunPod GPU.

## 🛡️ Code Standards & Invariants

* **Zero Code Comments**: Self-documenting code through clear naming and small functions.
* **Strict TypeScript**: Full type safety, dedicated `tsconfig.scripts.json` with Node types.
* **English Only**: All identifiers, types, schemas, and logs are strictly in English.
* **Monorepo Build Gate**: Always passes `npm run check:build` across all 8 projects.
